# Real-data tokenizer decision

The original synthetic32768 BPE is preserved and assessed on bounded deterministic held-out real documents. Samples cover Python,C,C++,Rust,Java,Go,JavaScript,TypeScript,C#,HTML/CSS,SQL,Bash,technical English and additional long-tail languages. JSON/YAML come from real fenced blocks in held-out repository documentation. Sample counts differ for scarce categories and are explicitly reported; bounded samples limit precision rather than establishing universal coverage. Final assessment has30 documents for each priority code language, English and technical English,30 YAML blocks and21 JSON blocks. Some long-tail languages have2–24 documents; detailed per-language counts/hashes remain in the JSON.

Measure tokens/character, tokens/UTF8 byte, tokens/line, approximate standalone regex identifier fragmentation and identifiers>=20 characters, exact encode/decode roundtrip. Additional probes test tabs/indentation/newlines, Unicode/non-Latin/emoji, operators/punctuation and rare library identifiers. These are descriptive tokenizer metrics, not coding quality or token-equivalent NLL.

A single bounded candidate trains a byte-level32768 BPE with min-frequency3, full byte alphabet and existing structural/tool/memory markers plus `<fim_prefix>`, `<fim_suffix>`, `<fim_middle>`. Fit only documents assigned TRAIN by the frozen repository/domain split, with per-category/language character caps to prevent domination. Some fitting-reservoir documents can be excluded by later LM token quotas; no validation text enters fitting. Training document hashes/counts/stratum characters are retained in tokenizer_training_metadata.json. The pre-freeze corpus rebuild does not change split assignments or the candidate weights.

Predeclared replacement criterion:>=15% median real-code token reduction and exact measured roundtrips, while retaining32768 embedding cost. The initial representative sample shows45.82% reduction; the expanded final held-out assessment shows45.17%. Candidate tokenizer bytes are unchanged between assessments. No48k/64k sweep is needed at this micro scale. All tested text/probes roundtrip exactly; whitespace is preserved and FIM is supported for future work, without FIM-heavy training here.

Chosen tokenizer: data/research_v1/tokenizer.json. SHA256:832daf453fc64e28f50df00ac2e458718576bb26e3f16e737f18b120ae4e309a. All three architectures use exactly these bytes and vocabulary. Tokenizer evaluation/decision JSONs are machine-readable evidence. Absolute NLL is compared only within this real-data tokenizer; old synthetic NLL values cannot be directly subtracted.
